# Правила работы с Git

## 1. Инструмент для работы с Git

Для работы с Git используется **SourceTree**.
Все операции (создание веток, коммиты, push/pull, слияния) выполняются через интерфейс SourceTree.

---

## 2. Ветка main

`main` — релизная (основная) ветка проекта.

- Является главной веткой репозитория
- Содержит только стабильный, готовый к релизу код
- Прямые коммиты в `main` запрещены
- Любые изменения попадают в `main` только через Pull Request

---

## 3. Ветки для задач

Каждая новая задача выполняется в отдельной ветке, созданной от актуального состояния `main`.

### 2.1. Именование веток

Формат названия ветки:

```
H-<номер задачи>
```

**Пример:**

```
H-123
```

где `123` — номер задачи в трекере Trello.

---

## 4. Коммиты

Название коммита соответствует названию задачи.

**Пример:**

Задача: *«H-123 Добавить экран новостей»*

Коммит:
"H-123 Добавить экран новостей"

**Рекомендации по коммитам:**
- Один коммит — одно логическое изменение
- Сообщение коммита начинается с номера задачи (`H-<номер>`)
- Далее — краткое описание сути изменения в повелительном наклонении («Добавить», «Исправить», «Обновить»)

---

## 5. Слияние с main

Слияние рабочей ветки в `main` происходит **только через Pull Request (PR)**.

### 4.1. Процесс

1. Разработчик завершает работу в своей ветке (`H-123`)
2. Пушит ветку в удалённый репозиторий:
3. Создаёт Pull Request из `H-123` в `main`
4. PR проходит код-ревью
5. После одобрения PR вливается в `main`

### 4.2. Требования к Pull Request

- Заголовок PR соответствует названию задачи (`H-<номер задачи>: <описание>`)
- Прямой push в `main`, минуя PR, запрещён

---

## 6. Автоматическое удаление рабочей ветки после слияния

Репозиторий настраивается так, чтобы рабочая ветка автоматически удалялась после успешного слияния PR в `main`.

### 5.1. Настройка (пример для GitHub)

1. Перейти в настройки репозитория: **Settings → General**
2. В разделе **Pull Requests** включить опцию:
   - **Automatically delete head branches**
3. Сохранить изменения

После включения этой настройки, при каждом слиянии PR ветка-источник (например, `H-123`) будет автоматически удаляться из удалённого репозитория.

*Примечание: для GitLab аналогичная настройка находится в **Settings → Merge requests → Delete source branch when merge request is accepted**.*

---

## 7. Краткая схема флоу

main
 └── H-123 (ветка задачи, создана от main)
      │
      │  git commit -m "H-123 Добавить экран новостей"
      │
      └── Pull Request → main
                │
                ├── Код-ревью
                ├── Merge в main
                └── Автоматическое удаление ветки H-123
